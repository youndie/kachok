The peers column is the diagnosis. 24/4 · 61 is connected / unchoked · outstanding. Sortable on any of the three, so “which of my forty is starved” is one click.

Stopping is a state, not a spinner. A clean stop takes up to ten seconds — tracker, peers, flush, resume record — so the row stays, dimmed, with the last numbers it had.

Speeds are KiB/s in the header, numbers in the cell. Nothing in a row reflows when a number changes: fixed column widths, tabular figures, units named once.

A magnet has no name yet. The row shows the info hash in mono until MetadataFetcher returns, and an indeterminate bar rather than a percentage.

Both complaints are shown, verbatim. A 502 from the tracker and a reset peer are not the same problem, so they are not the same line — and neither hides behind a hover.

Custom drawing, flagged: the peers cell, the progress cell (bar + figure in one 92 px column), and the state glyph column. Everything else is stock M3.

Joining announces this machine's address to strangers, starting with three public bootstrap routers. kachok only needs it for a magnet link that names no tracker, so it is off until you ask. A private torrent never joins, whatever this says.

default off
bolt Changes apply to the running session immediately — no restart, no Apply button. planned

Every number here is a field on SessionConfig, and every default is one that was measured rather than guessed. So the default is printed beside the field instead of hidden in a blank: a user who changes the pipeline depth should be able to see what it was.

The DHT toggle is the only setting with a paragraph. It is off by default and the paragraph is why — a switch that announces your address to strangers earns an explanation next to it, not in a help page.

A limit of no limit is not a limit of zero. The field says the words; zero is not typeable.

NOT IN SETTINGS Theme (follows the system), choke interval, optimistic interval, flush and resume intervals, request timeout. They are SessionConfig fields with measured values and no user question behind them.
